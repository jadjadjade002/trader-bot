## ส่วนประกอบหลัก (Main Components)

### 1. Velocity M1

**ไฟล์ต้นทาง:**

- `QuantumTitan_v16_Velocity.mq5`

**บทบาทและหน้าที่:**

- ยิงออเดอร์ Scalp รวดเร็วตามโมเมนตัมระยะสั้น
- เป็นส่วนประกอบที่รับผิดชอบการเทรดส่วนใหญ่ที่เกิดขึ้นจริงในบัญชีขณะนี้

**พารามิเตอร์หลัก (Core Inputs):**

- Magic number: `991602`
- Base lot: `0.01`
- Max spread: `60 points`
- Take profit (TP): `180 points`
- Stop loss (SL): `260 points`
- Breakeven trigger: `85 points` (ระดับกำไรที่เริ่มขยับ SL มากันทุน)
- Breakeven lock: `15 points` (ระยะบวกที่ล็อกกำไรไว้เหนือจุดเปิด)
- Cooldown: `1` แท่ง M1 หลังปิดออเดอร์

**ตรรกะการเปิดออเดอร์ (Entry Logic):**

- จะเทรดเมื่อ **ไม่มี** Position เดิมของ Velocity ค้างอยู่ในสินทรัพย์และ Magic number เดียวกันเท่านั้น
- Spread ต้องต่ำกว่าค่า `InpMaxSpreadPoints`
- ประเมินสัญญาณเพียง **ครั้งเดียวต่อการเริ่มแท่ง M1 ใหม่**
- ใช้ข้อมูลจาก **แท่ง M1 ที่เพิ่งปิดสมบูรณ์แล้วเท่านั้น** ไม่ใช้แท่งที่กำลังฟอร์มตัวอยู่

**เงื่อนไขการเข้า BUY:**

- เส้น EMA14 อยู่เหนือ EMA50
- แท่งเทียนที่ปิดสมบูรณ์แล้วปิดเหนือ EMA50
- แท่งเทียนย่อตัวกลับลงมาใกล้แนว EMA14 (Pullback)
- มีแรงปฏิเสธราคาฝั่งล่าง (Lower wick rejection) หรือปิดเป็นแท่งเขียว (Bullish close)
- โมเมนตัม Squeeze ไม่ได้เป็นขาลงรุนแรง
- RSI อยู่ในช่วงโมเมนตัมที่อนุญาตให้เปิดออเดอร์

**เงื่อนไขการเข้า SELL:**

- เส้น EMA14 อยู่ต่ำกว่า EMA50
- แท่งเทียนที่ปิดสมบูรณ์แล้วปิดต่ำกว่า EMA50
- แท่งเทียนดีดตัวกลับขึ้นมาใกล้แนว EMA14 (Pullback)
- มีแรงปฏิเสธราคาฝั่งบน (Upper wick rejection) หรือปิดเป็นแท่งแดง (Bearish close)
- โมเมนตัม Squeeze ไม่ได้เป็นขาขึ้นรุนแรง
- RSI อยู่ในช่วงโมเมนตัมที่อนุญาตให้เปิดออเดอร์

**การบริหารจัดการ Position (Position Management):**

- เมื่อออเดอร์ BUY ทำกำไรถึงจุดทริกเกอร์ Breakeven ระบบจะขยับ SL ไปยัง `ราคาเปิด + Lock Buffer (15 points)`
- เมื่อออเดอร์ SELL ทำกำไรถึงจุดทริกเกอร์ Breakeven ระบบจะขยับ SL ไปยัง `ราคาเปิด - Lock Buffer (15 points)`
- ทำการเช็ก `PositionSelectByTicket()` ก่อนแก้ไขออเดอร์เสมอเพื่อความปลอดภัย
- เริ่มนับเวลา Cooldown ทันทีเมื่อตรวจพบว่าออเดอร์ถูกปิด (Deal Close)

**พฤติกรรมในทางปฏิบัติจริง:**

- ออเดอร์ที่ชนะมักมีกำไรขนาดเล็กและปิดไว
- ฟังก์ชัน Breakeven Lock คือกลไกสำคัญที่เปลี่ยนการ Scalp ที่มีความเสี่ยงให้กลายเป็นผลกำไรเล็กน้อยหรือปิดแบบป้องกันเงินทุน
- ค่า Spread มีผลกระทบอย่างยิ่งเนื่องจากระยะเป้าหมาย TP มีเพียง `180 points`

### 2. Apex M5

**ไฟล์ต้นทาง:**

- `QuantumTitan_v16_Apex.mq5`

**บทบาทและหน้าที่:**

- บน VM ล่าสุด ตรวจพบคอนฟิกโปรไฟล์ที่ใช้งานคือ `M5 FAST INTRADAY`

**โปรไฟล์ที่ใช้งานจริงในปัจจุบัน:**

- Timeframe: `M5`
- Magic number: `991605`
- กรอบเวลาอ้างอิงระดับสูง (Higher Timeframe): `H1`
- Min buffer: `450 points`
- SL multiplier: `1.40`

- Grid step: `1.20 ATR`

**โมดูลย่อยของ Apex:**

- `AlphaScoring.mqh`
- `TrailingSafety.mqh`
- `DynamicGrid.mqh`
- `TelemetryHUD.mqh`

**ขั้นตอนการทำงานในแต่ละ Tick (Main Tick Flow):**

- ตรวจสอบสิทธิ์การเทรดของ Terminal และ EA (Automated Trading Permission)
- ตรวจสอบว่าสินทรัพย์อนุญาตให้ส่งคำสั่งเทรดได้
- อ่านค่า ATR จาก Timeframe ของกราฟ

- อัปเดตการบริหารจัดการ Trailing Stop และ Breakeven
- ตรวจสอบเงื่อนไขการปิดรวบพอร์ต (Basket Close)
- คำนวณคะแนน AlphaScoring
- อัปเดตการวาด HUD บนหน้าจอ 1 ครั้งต่อวินาที
- จัดการวางเลเยอร์ Grid หากมี Basket เปิดค้างอยู่
- ประเมินสัญญาณเข้าออเดอร์ Alpha ใหม่เพียงครั้งเดียวเมื่อมีแท่งเทียนใหม่เกิดขึ้น

### 3. AlphaScoring

**ไฟล์ต้นทาง:**

- `Include/QuantumTitan/AlphaScoring.mqh`

**บทบาทและหน้าที่:**

- คำนวณและประเมินคุณภาพของสัญญาณทิศทางตลาด (Signal Quality)
- Apex นำคะแนนนี้ไปใช้ตัดสินใจว่าเข้าเงื่อนไขอนุญาตให้เปิดออเดอร์ BUY หรือ SELL หรือไม่

**ปัจจัยที่นำมาคิดคะแนนเชิงทฤษฎี:**

- ทิศทางแนวโน้มของกรอบเวลาที่ใหญ่กว่า (Higher Timeframe Direction)
- โซนราคาถูกหรือแพง (Discount vs Premium Zone)
- โซนความไม่สมดุลของราคา (Fair Value Gap / Imbalance)
- พฤติกรรมการกวาดสภาพคล่อง (Liquidity Sweep)
- บริบทของโซนคำสั่งซื้อขายสถาบัน (Order Block Context)
- แท่งเทียนส่งแรงกระชาก (Displacement)
- สัญญาณหมดแรงของโมเมนตัม (RSI Exhaustion)
- แรงบีบอัดของราคา (Squeeze Momentum)
- โครงสร้างเส้นค่าเฉลี่ย (EMA Structure)
- การขยายตัวของปริมาณการซื้อขาย (Volume Expansion)
- ตัวกรองช่วงเวลาทองคำ (Killzone / Trading Session Filter)

*สำหรับโปรไฟล์ M5 Apex เกณฑ์คะแนนขั้นต่ำ (Threshold) ที่ตั้งไว้คือ `75` คะแนน*

## สาเหตุที่บอททำกำไรได้ในการรันรอบล่าสุด

ผลการเทรดที่เป็นบวกในระยะหลังเกิดจากรูปแบบการทำงานร่วมกันดังนี้:

- Velocity ตรวจจับคลื่นโมเมนตัมระยะสั้นบน M1
- เข้าเปิด Scalp ขนาด 0.01 lot อย่างรวดเร็ว
- เลื่อน SL มากันทุนทันทีหลังจากราคาวิ่งถูกทางไปได้เล็กน้อย
- ออเดอร์หลายไม้สามารถแตะเป้าหรือปิดทำกำไรได้ก่อนที่โมเมนตัมจะหมดแรง
- Apex M5 รันควบคู่เป็นโครงสร้างควบคุมภาพรวมและมอนิเตอร์ความปลอดภัย

*ผลงานจะดีเมื่อ XAUUSD มีโมเมนตัมสั้นๆ ที่ชัดเจน แต่จะเปราะบางเมื่อ Spread ถ่างกว้าง, เกิดสภาวะราคาสะบัดไปมา (Whipsaw) หรือส่งคำสั่งเทรดคลาดเคลื่อน (Slippage)*

## ความเสี่ยงหลักในการใช้งานจริง (Main Real-Use Risks)

### ความเสี่ยงจากค่า Spread (Spread Risk)

ระยะ TP ของ Velocity ค่อนข้างแคบ:

- TP: `180 points`
- SL: `260 points`

หากโบรกเกอร์มีค่า Spread ที่ถ่างกว้าง ค่าคาดหวังทางสถิติ (Expected Value) อาจพลิกจากกำไรเป็นขาดทุนได้อย่างรวดเร็ว โดยเฉพาะอย่างยิ่งบนบัญชีจริงของโบรกเกอร์ เช่น XM

มาตรการควบคุมที่แนะนำก่อนนำไปใช้กับเงินจริง:

- กำหนดตัวกรองตัดการทำงานเมื่อ Spread เกินกำหนดอย่างเข้มงวด (Hard MaxSpread Gate)
- ระงับการเทรดช่วงเวลาเปลี่ยนวันของเซิร์ฟเวอร์ (Rollover Block)
- ระงับการเทรดช่วงมีข่าวตัวเลขเศรษฐกิจสำคัญของสหรัฐฯ (High-impact USD News Block)
- เก็บ Log สถิติการกระจายตัวของ Spread บนประเภทบัญชีจริงที่จะใช้งาน

### ความเสี่ยงจากราคาสะบัดหลอก (Whipsaw Risk)

Velocity อาจเข้าออเดอร์ตามแท่งโมเมนตัมสั้นๆ แล้วราคาเกิดการกลับตัวรุนแรงในทันที

นี่คือความเสี่ยงประเด็นเดียวกับที่โครงการวิจัย V21 Research กำลังทำการเก็บข้อมูลผ่าน Forward Collector และพัฒนาระบบ Whipsaw Gate มาป้องกัน

### ความเสี่ยงจากภาระรวมของ Grid (Grid Exposure Risk)

Apex M5 มีโมดูล DynamicGrid ทำงานอยู่และสามารถเปิดได้สูงสุด `4` ไม้ แม้ขนาดล็อตจะฟิกไว้เล็กที่ 0.01 แต่หากตลาดลากยาว ความเสี่ยงรวม (Exposure) ก็ยังสะสมสูงขึ้นได้

### ความแตกต่างระหว่างบัญชีทดลอง (Demo) กับบัญชีจริง (Real Execution)

บัญชีที่สังเกตการณ์ในปัจจุบันเป็นบัญชี Demo การใช้งานบนบัญชีเงินจริงอาจมีผลลัพธ์ที่แตกต่างกันจากปัจจัยเหล่านี้:

- ค่า Spread ที่กว้างกว่าหรือผันผวนกว่า
- อาการ Slippage (ราคาคลาดเคลื่อน)
- ปัญหา Requotes หรือข้อจำกัดเรื่อง Order Filling Mode
- การจับคู่คำสั่ง Stop Order ในช่วงตลาดมีความผันผวนสูง
- ปัญหาสภาพคล่องในช่วงข้ามคืน (Rollover Liquidity)

## แนวทางปฏิบัติการ (Operational Rule)

ข้อแนะนำและข้อกำหนดในปัจจุบัน:

- ห้ามแก้ไขปรับแต่ง Instance ของ V16 ที่กำลังรันสดอยู่ ในขณะที่ระบบยังคงทำกำไรและทำงานได้อย่างเสถียร
- เฝ้าสังเกตการณ์และ Monitor ผลของ V16 แยกต่างหาก
- ให้ V21 ทำหน้าที่เป็นเพียงตัวเก็บข้อมูลไปข้างหน้า (Collector-only) เท่านั้น
- คงสถานะไม่อนุมัติ (Rejected) สำหรับ V21.67
- กำหนดให้ V22 เป็นโครงการวิจัยแบบออฟไลน์ (Offline Research) จนกว่าจะได้รับอนุมัติอย่างเป็นทางการ
